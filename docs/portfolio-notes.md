# 이력서·포트폴리오 작성 메모

저장소의 산출물로 뒷받침할 수 있는 표현을 모았다. 실제 본인의 참여 범위와 설명 가능한 수준에 맞춰 조정한다. 구현과 조사에는 AI 도구를 활용했다.

## 한 줄 소개

**오픈소스 geo-sleuth의 사진 위치 조사 절차를 분석·검증하고, 실제 조사 실행과 근거 리포트를 연결하는 FRAME 로컬 웹 프로토타입을 기획·구현한 프로젝트.**

## 짧은 프로젝트 소개 예시

사진의 촬영 장소를 좌표만으로 전달하면 판단 근거와 정확도를 검토하기 어렵다는 문제에서 시작했습니다. geo-sleuth의 도구와 실제 사진 조사 결과를 분석한 뒤, 사진 의뢰·실시간 진행 기록·근거 리포트·실패 복구를 제공하는 FRAME 프로토타입으로 연결했습니다. 카메라 추정점과 장소 대표점을 구분하고, 이미지·지도 검증 결과와 미확정 사항을 사용자에게 표시하도록 구성했습니다.

## 이력서 항목으로 정리할 수 있는 내용

- Node.js와 JavaScript ES 모듈로 사진 의뢰, Codex CLI 조사, SSE 진행 기록, 구조화된 결과 리포트를 연결하는 로컬 웹 프로토타입 구현.
- 파일 기반 작업 대기열, 중지·복원, 모델 혼잡 제한 재시도, 체크포인트와 중간 자료 이어받기로 조사 실행의 복구 흐름 구성.
- 빈 JSON·손상 이미지·실패 지도 타일·실제 도구 실행 여부를 확인하고, 장소 대표점과 카메라 추정점을 구분하는 결과 검사 도입.
- geo-sleuth 조사·재검증 7개 작업 폴더와 FRAME 실제 실행 5건을 근거 이미지·JSON·계산 기록과 함께 정리.
- 한국 주소·동명 장소·로드뷰·좌표 해석 지침을 외부 지역팩으로 구성해 원본 스킬 수정 없이 연결.

자동 검사 수치는 [최신 검증 기록](validation.md)의 실제 통과 수와 검사 범위를 함께 인용한다. 자동 계약 테스트는 위치 정확도 실험과 구분한다.

## 강조하기 좋은 기술적 문제 해결

| 문제 | 접근 | 보여줄 근거 |
|---|---|---|
| ‘좌표가 있음’과 ‘촬영점이 확인됨’의 혼동 | 좌표 의미·수준별 신뢰도·보류 상태 분리 | 도메인 코드, 결과 JSON, 리포트 |
| 이미지 파일만 생기면 지도가 성공한 것으로 보임 | 해독·메타데이터·실패 타일까지 검사 | assets·quality 코드, 테스트 |
| 동일한 다운로드가 Windows 환경에서 실패 | Python HTTPS와 curl 대조 후 worker 범위 전송 보완 | 전송 어댑터, QA·전송 테스트 |
| 모델 혼잡으로 중간 조사 유실 | 제한 재시도·세션 복구·파일 기반 이어받기 | worker·recovery 코드, 테스트 |
| 좌표가 실제 값에 가까워도 추정이 불안정 | 점 제외·좌표 변동·높이 조건·해안선 대조 | 사근진 민감도·검증 기록 |

## 사근진 사례를 설명하는 방법

**권장 표현:** “야간 해안 사진에서 지도·사진 대응점으로 카메라 위치를 조건부 계산하고, 사용자 제공 좌표와 4.65m 차이를 확인했다. 다만 81개 높이 조건과 좌표 변동 검사에서 결과의 민감도를 확인해 정밀 오차반경은 확정하지 않았다.”

함께 설명할 조건은 같은 사진과 실제 위치를 이전에 알고 있었던 재검증이라는 점이다. 이 수치를 독립 평가 정확도나 일반적인 성능으로 바꾸면 안 된다.

## 포트폴리오 구성 제안

1. 문제와 사용자: 촬영지를 찾아도 근거·방향·확인 과제가 남는다.
2. 제품 흐름: 의뢰 → 진행 → 리포트 → 보완.
3. 기술 구조: 로컬 서버·CLI·스킬·파일 계약·SSE.
4. 대표 문제 해결: 실패 지도와 복구, 좌표 의미 구분.
5. 사례 검증: 가까운 계산값과 불안정성을 함께 보여준다.
6. 현재 한계와 다음 평가: 블라인드 정확도·보류율·사용성·비용.
