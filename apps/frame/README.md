# FRAME — localhost 실시간 촬영지 리서치

사진 접수 → Codex CLI + 기존 geo-sleuth 조사 → 실시간 진행 기록 → 촬영지 리포트 자동 연결.
Sites에 배포했던 FRAME 화면을 사용하는 로컬 전용 앱입니다. 이번 변경은 Sites에 배포하지 않습니다.

## 실행

이 폴더에서 PowerShell을 열고 실행합니다.

```powershell
npm run dev
```

<http://localhost:4173> 에 접속합니다. Node.js 18 이상, Codex CLI, Python 3.10 이상, uv, geo-sleuth 스킬이 필요합니다. Node 패키지 추가 설치는 없습니다.

1. 리서치 의뢰에서 사진을 올리거나 공개 샘플 사진을 선택합니다.
2. 실행 환경 확인이 준비 완료인지 확인하고 제목·요청사항을 입력합니다.
3. **리서치 시작하기**를 누르면 실제 Codex 조사가 시작되고 실시간 화면으로 이동합니다.
4. 조사 단계, 실제 도구 실행 안내, 공개 진행 메시지, 경과 시간을 확인합니다.
5. 완료되면 **촬영지 리포트 보기**를 누릅니다. 위치를 확정하지 못했으면 확인된 범위와 남은 사항을 표시합니다.

실제 모델 및 외부 조사 서비스를 사용합니다. 현재 PC의 Codex 로그인과 해당 계정의 사용량을 사용합니다. 사진은 조사에 필요한 모델·이미지 검색 서비스로 전송될 수 있습니다. 원본 사진·의뢰·기록·결과는 이 PC의 `.local-data/`에 저장합니다. 서버는 127.0.0.1에만 바인딩합니다.

## 진행 화면

- 사진과 요청, 조사 준비 → 사진 분석 → 후보 조사 → 근거 대조 → 리포트 작성 단계.
- Codex JSONL 이벤트와 작업자가 작성한 progress.json을 SSE로 실시간 전달.
- 실제로 확인된 단계만 변경합니다. 남은 시간이나 완료율은 추정하지 않습니다.
- Codex 내부 추론과 원시 명령 출력은 고객 화면에 보내지 않습니다.
- 브라우저를 닫아도 서버가 켜져 있으면 작업은 계속됩니다. 같은 URL로 돌아오거나 새로고침하면 저장된 기록과 다시 연결됩니다.
- 중지·실패 후 중간 자료 이어받기와 새 조사를 구분합니다. 이전 파일은 보존하며 이어받기는 자료를 복사한 새 조사 시도로 진행합니다.
- 서버가 종료되면 진행 작업을 중단으로 표시합니다. 서버를 다시 켠 뒤 해당 의뢰에서 재시작합니다.
- 동시 실행은 1건입니다. 추가 의뢰는 대기열에 넣습니다. 기본 작업 제한은 15분입니다.
- 실패 시 로그인·한도·권한·연결 오류에 맞는 안내를 표시합니다. 네트워크 재연결 중에도 서버 조사는 계속됩니다.

## 실행 환경

PATH의 Codex CLI 또는 설치된 Codex 데스크톱 앱의 번들 CLI를 자동 탐색합니다. 현재 사용자 프로필의 `.codex` 인증·설정과 `.codex/skills/geo-sleuth`를 사용합니다. 키나 인증 토큰을 앱 폴더에 복사하지 않습니다. Codex는 `workspace-write`로 실행하며 작업 폴더 쓰기와 조사용 네트워크를 허용합니다. 샌드박스 전체 해제 옵션은 사용하지 않습니다.

uv 캐시와 모델 캐시는 `.local-data/runtime/`에 둡니다. 개별 스크립트의 Python 의존성은 uv가 처음 사용할 때 설치할 수 있습니다. 모델 가중치는 캐시를 확인하고 남은 실행 시간 안에서 내려받도록 요청합니다. 검색 서비스 차단·CAPTCHA·자료 부족은 실제 결과에 한계로 표시합니다.

Codex 설치 후 일반 터미널에서 `codex login`으로 로그인할 수 있습니다. 이 앱에서 사용자 로그인 화면을 대신 조작하지 않습니다. Codex가 사용자 폴더에 쓸 수 없는 제한된 터미널에서는 일반 PowerShell에서 서버를 실행하세요.

필요한 경우 실행 전에 환경 변수를 지정합니다.

```powershell
$env:PORT=4174
$env:FRAME_GEO_SKILL='C:\Users\admin\.codex\skills\geo-sleuth'
$env:FRAME_JOB_TIMEOUT_MS=900000
npm run dev
```

- FRAME_CODEX_BIN: Codex 실행 파일의 경로. 기본 codex.
- FRAME_DATA_DIR: 저장 폴더의 절대 경로. 기본 프로젝트의 .local-data.
- FRAME_GEO_SKILL: geo-sleuth 스킬 폴더.
- FRAME_JOB_TIMEOUT_MS: 작업 시간 제한, 밀리초.
- PORT: 기본 4173.

## 결과와 수동 보완

의뢰별 `.local-data/requests/<id>/state.json`에 접수 정보와 진행 기록을 저장하고, `runs/<시도 번호>/`에 TASK.md, 원본 사진, 요청, JSON Schema, final.json, 실제 조사 파일, 원시 이벤트·오류 로그를 저장합니다. 원시 로그는 로컬 점검용이며 웹 API로 공개하지 않습니다. 결과에서 지정하고 실제로 생성된 근거 이미지 파일만 웹에서 제공합니다.

최종 응답은 Codex `--output-schema`로 FRAME JSON 형식을 지정합니다. 확인된 카메라 좌표·오차 반경·근거 파일·신뢰도 조건을 만족하면 완성, 그렇지 않으면 추가 확인 상태로 연결합니다. 장소 대표점·지역 참고점·카메라 위치는 coordinate_type으로 구분하여 표시합니다. 자동 결과는 현장 확인을 대신하지 않습니다.

스튜디오의 JSON 가져오기·결과 편집·이미지 추가·미리보기·전달도 유지합니다. 조사 중 수정은 차단하며 먼저 중지해야 합니다. 의뢰 백업·PDF 저장을 지원합니다. 목록에서 삭제하면 의뢰 기록을 제거하지만 조사 파일은 복구를 위해 디스크에 보존합니다. 삭제를 보장하는 서비스용 기능은 아직 없습니다.

별도 샘플 리포트는 화면 구성 예시로 표시합니다. 새 의뢰에서 샘플 사진을 선택하면 실제 Codex 조사를 실행하며 예시 결과를 자동으로 넣지 않습니다.

```powershell

```

백엔드 계약 테스트는 테스트 전용 자식 프로세스로 이벤트 전송, 결과 이미지 연결, 경로 차단, 중지·대기열, 인증 실패, 디스크 복원, 외부 Origin 차단을 검증합니다. 테스트 프로세스는 실제 앱 실행에 사용되지 않습니다. 외부 모델·검색 서비스가 정상인지와 실제 조사 품질은 별도 실사례로 확인합니다.

## 주요 파일

- server.mjs: localhost 정적 화면·접수 API·SSE.
- lib/jobs.mjs: 파일 저장·대기열·Codex 실행·중지·결과 연결.
- lib/runtime.mjs: 실행 환경 확인·CLI 인자·이벤트 변환·JSON Schema.
- dist/app.js, dist/lib/live.js, dist/live.css: 기존 UI와 실시간 진행 화면.
- dist/lib/store.js: 로컬 서버 연결.
- dist/lib/domain.js: 결과 정규화·입출력 계약.

현재는 개인 PC에서 시연하는 앱입니다. 다중 사용자 인증·외부 공개·클라우드 배포는 포함하지 않습니다.

## 2026-11-02 조사 품질 보강

FRAME 작업 실행 인자에 --model gpt-6.1-sol 및 model_reasoning_effort="medium"을 명시합니다. PC 전역 설정은 변경하지 않습니다. 접수 화면 환경 확인과 새 의뢰 진행 화면에 모델을 표시합니다.

기존의 5분 조기 종료·ML 다운로드 회피 지시는 제거했습니다. 기본 15분 실행 제한 안에서 유력 지역 이후 거리사진·근거리 특징 대조, match.py 순위화, 위치·방위 기하 검증을 수행하도록 요청합니다. 외부 서비스 차단·자료 부족 시 시도·차단 이유와 빠진 검증을 기록합니다. 지시만으로 항상 동일한 조사 결과를 보장하지는 않습니다.

결과 계약은 camera_estimate, radius_basis, heading_basis, hfov, confidence_levels(도시/지역/도로/촬영점), verification(거리사진/순위화/기하 검증), evidence_spec을 포함합니다. 기존 JSON도 읽되 새 필드가 없으면 미평가로 표시합니다.

서버는 실제 uv run 도구 실행 이벤트와 검증 참조 파일을 확인합니다. 도움말·소스 읽기·확인된 스크립트 오류는 검증 성공에 포함하지 않습니다. evidence_spec의 촬영점·방향, 비교 패널과 원본 지도 메타데이터도 확인합니다. 누락 시 추가 확인 상태로 결과를 전달하며, 조사자가 적은 추정값을 임의로 제거하지 않습니다. 이는 실행·구조 검사이며 사진 대조의 의미적 정확성을 독립적으로 증명하지 않습니다.

원본 위성 지도와 타일 메타데이터가 있으면 리포트에서 파란 점선으로 위치 추정 반경, 노란 선으로 방위각, 부채꼴로 hfov를 별도로 표시합니다. 세 값은 서로 다른 의미입니다. 지도 범위 밖의 좌표나 미확정 값은 표시를 생략하고 안내합니다.

기존 결과는 유지합니다. 기존 의뢰의 '조사 과정과 실행 기록 보기' → '새로 조사'를 누르면 새 절차로 다시 실행합니다. 재시작 직전 결과는 해당 의뢰의 history 폴더에 보관합니다. 새 조사는 계정 사용량을 소비합니다.

## 2026-11-03 모델 선택

새 의뢰의 '분석 모델'에서 GPT-6.1 Sol, GPT-6.1 Terra, GPT-6.0 Luna를 선택합니다. Luna의 공식 실행 식별자는 gpt-6-luna입니다. 추론은 모든 모델에서 high로 고정하며 서버가 직접 실행 인자에 적용합니다. 기본 선택은 Sol입니다.

기존 의뢰도 실시간 기록 화면에서 모델을 선택하고 '새로 조사'할 수 있습니다. 선택은 의뢰·시도별로 저장하며 기록·리포트에는 실제 해당 시도의 설정을 표시합니다. 기존 완료 결과의 모델 표시는 소급 변경하지 않습니다. 계정에서 사용할 수 없는 모델은 명시적 실패로 표시하고 다른 모델로 자동 대체하지 않습니다.

접수→실제 자식 프로세스 인자→기록 보존→모델 변경 후 재시작 경로를 테스트용 프로세스로 검증합니다. 각 모델의 실제 유료 추론은 자동 검사에서 호출하지 않습니다.

## 2026-11-03 한국 지역팩

region-packs/kr에 최소 한국 자료팩(region.json, clues.md, services.md)을 추가했습니다. 기존 스킬의 확장 환경 변수 GEO_SLEUTH_REGIONS로 연결하므로 전역 스킬을 수정하지 않습니다. 추가 설정된 외부 팩 경로는 보존하며 뒤쪽 경로가 우선합니다. 한국이 근거 있는 후보가 되면 regions.py show kr로 읽도록 작업 지시도 연결했습니다.

6개 단서 항목: 도로명+건물번호, 동명 장소·상호 구분, 로드뷰 근경 대조, Google 조회 실패의 해석, 좌표계·위경도 순서, 방위각·시야각 구분. 한국어·영문 OSM 이름과 --region kr 검색을 지원하며 카카오 공식 공개 링크 안내를 포함합니다. 표 기반 전화 지역번호·번호판 데이터와 별도 지도 서비스 어댑터는 포함하지 않는 초기 자료팩입니다.

geo-sleuth 자체 lint kr와 show 대한민국를 실제 worker 환경으로 실행해 성공을 확인했습니다. 지역팩은 TLS·모델 용량 오류를 해결하지 않습니다. 단독 Codex 세션에서 쓰려면 region-packs/README.md의 환경 변수 설정을 사용하세요.


## 2026-11-03 실행 안정화

1. 네트워크: 모델 호출 전 동일한 Windows 샌드박스에서 Python HTTPS와 Windows curl을 비교합니다. 이 PC에서는 Python 성공 / curl Schannel SEC_E_NO_CREDENTIALS를 재현했습니다. FRAME worker의 PYTHONPATH/sitecustomize에 한정해 geo-sleuth Python 스크립트의 curl 호출을 표준 urllib HTTPS로 전환합니다. 인증서 검증을 유지하고 GEO_PROXY/direct를 일관되게 적용합니다. 전역 스킬·Python·Codex 설정은 변경하지 않습니다. 브라우저 역검색 업로드와 ML 라이브러리의 통신은 해당 클라이언트 경로를 사용하므로 이 어댑터의 적용 대상이 아닙니다. HTTP 403/406/429는 서버 도달과 서비스 사용 가능 여부를 구분합니다. 모든 HTTPS 경로가 실패하면 모델 호출 전에 중단합니다.
2. 오류: 혼잡, 모델 접근 불가, 인증, 사용량, 호출 빈도, TLS, 네트워크 권한, 파일 권한, 없는 도구, 명령 형식, 인코딩, HTTP 거절, 손상된 자료, 정상 자료 없음, 시간 초과를 별도 코드와 안내로 기록합니다. 원시 로그는 로컬에만 남기며 비공개 추론은 UI에 표시하지 않습니다.
3. 도구: 조사 시작 때 설치된 scripts의 실제 목록으로 tools.json/TOOL_GUIDE.md를 생성합니다. python tools/run_tool.py 경로의 실행기가 허용 목록을 검사한 뒤 uv run으로 개별 도구를 실행하고 .tool-receipts에 결과를 남깁니다. 도움말과 실패는 검증 성공에서 제외합니다. 복잡한 코드는 UTF-8 .py 파일로 실행하도록 지시합니다. CLI 전체를 이 실행기만 쓰도록 OS 수준으로 제한하는 것은 아닙니다.
4. 자료: 다운로드는 완전한 성공 응답만 임시 파일에서 원자적으로 교체합니다. 이미지 경로의 HTML 응답을 거절하고, 최종 근거는 Pillow로 verify 및 실제 decode합니다. 빈 파일/빈 JSON/서비스 오류 JSON, 일부라도 실패한 지도 타일, 지도 크기 불일치를 검증 실패로 처리합니다. 지도 메타데이터의 failed_tiles=0이 필수입니다. 파일이 존재한다는 이유만으로 검증 성공으로 올리지 않습니다. 실패 자료는 완성 리포트의 지도·근거에서 제외하고 추가 확인 상태와 검사 경고를 남깁니다.
